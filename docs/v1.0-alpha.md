# Novella v1.0 Alpha

v1.0 Alpha is the first release-shaped milestone. It keeps the implementation script-only for easy installation and review, while adding the packaging and validation tools needed to ship the addon safely.

## Included

- Release manifest describing version, license, repository, Godot compatibility, required files, package roots, and forbidden paths.
- Release validator used by both Godot tests and PowerShell release checks.
- `scripts/validate-release.ps1` for tracked-file validation, version consistency checks, forbidden-path checks, and optional Godot tests.
- `scripts/package-addon.ps1` for producing `dist/novella-<version>.zip` via `git archive` from explicit package roots.
- GitHub Actions release check that validates tracked release files without downloading or committing a Godot engine.
- `examples/scripts/v1_0_showcase.nvs`, a single script demonstrating runtime, presentation, interaction, localization, gallery, replay, and achievement features.
- Version alignment between `plugin.cfg` and `Constants.VERSION`.

## Packaging

Create a local addon package:

```powershell
.\scripts\package-addon.ps1
```

The package script first runs release validation, then archives only explicit tracked roots:

- `addons/novella`
- `docs`
- `examples`
- `scripts`
- `README.md`
- `LICENSE`
- `project.godot`

Generated packages land in ignored `dist/`.

## Validation

Run release validation and the full local Godot test suite:

```powershell
.\scripts\validate-release.ps1
```

Run only tracked-file and version validation:

```powershell
.\scripts\validate-release.ps1 -SkipGodotTests
```

The validator rejects tracked Godot engine downloads, editor caches, export templates, build artifacts, local requirement/progress documents, logs, and temporary files.

## Compatibility

- Primary runtime: Godot 4.6.
- Compatibility target: Godot 4.3+ in the Godot 4 line.
- Local verification in this workspace currently uses Godot 4.6.2 Mono.
- Godot 4.3, 4.4, and 4.5 compatibility remain API-targeted until those runtimes are installed and tested locally or in a self-hosted matrix.
